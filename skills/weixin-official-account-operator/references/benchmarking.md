# 热门文章对标

成稿生硬的根因通常是「凭空写」：没有看过这个赛道里真正被传播的文章长什么样。
动笔前先建立对标池，把别人的**结构技法**拆出来，再用自己的主题和素材重写。
对标是为了学「怎么讲」，不是为了拿「讲什么」——事实、案例、观点必须自产或另行核实。

## 何时进入本文件

- 用户给了主题（或模糊想法），准备选题、写提纲或成稿之前。
- 用户明确要求「参考爆款」「看看别人怎么写」「按这个风格改写」。
- 成稿被判「太生硬/像 AI/像通稿」需要返工——先查 [voice.md](voice.md) 的口吻卡和真实素材是否缺位，
  再回到对标看结构，不要直接润色词句。

## 第一步：先锁主题简报（问不出来就不要开始找文章）

对标检索是围绕主题做的，主题不清会白检索一轮。最少问清这 5 项；
用户一次只答一部分时，用已答内容先跑一轮，再补问剩下的，不要空转等待：

| 项 | 要拿到的答案 | 追问示例 |
|---|---|---|
| 主题 | 一句话说清写什么（不是领域，是具体切口） | 「AI 提效」太宽，要「中小企业用 AI 写周报的 3 个坑」 |
| 读者 | 谁在什么处境下会点开 | 岗位/身份 + 他此刻的麻烦 |
| 目标 | `reach` / `follower_growth` / `leads` / `trust` 选一个主目标 | 主目标不同，结构完全不同 |
| 素材 | 手上有无真实案例、数据、经历 | 有素材才写得具体；没有就先说清，别编 |
| 禁区 | 不能说的、不想说的、必须说的 | 竞品、客户名、政治敏感、绝对化承诺 |

把简报回显成一段话让用户确认，再进入第二步。**用户拒绝补充且信息确实不足时，
明确说明「选题质量会受限」，按最保守的可写方向走，不要假装信息已足够。**

## 第二步：建立对标池（3–5 篇，三路来源按优先级）

### 路线 A：账号自有爆款（数据最可信，优先）

微信返回的阅读/分享/收藏是本账号唯一的真实热度证据：

1. `weixin_oa_list_published_articles`（带目标 `connection_id`）取近期列表。
2. 对候选文章用 `weixin_oa_get_article_stats_range`（单日时起止日期相同；`begin_date`/`end_date`，最多 7 天、需早于北京时间今天、
   发表数据仅支持 2025-11-01 及之后）取指标。
3. 挑出明显高于账号基线的 1–3 篇，用 `weixin_oa_get_published_article` 读正文与排版。
4. 这些篇目就是「这个号的读者已经用脚投票过的写法」，权重最高。

### 路线 B：联网检索同赛道热门（覆盖面广，热度需谨慎表述）

用当前环境的联网检索能力搜主题关键词，再取回可访问的正文页。
来源可以是公众号转载页、行业媒体、知乎/小红书同题内容；优先发布时间在近 12 个月内、且能读到全文的。

**热度口径必须诚实**：

- 能确认的写「检索到 N 篇，其中 M 篇来自 XX 类型站点」；
- 拿不到阅读量就说拿不到，**不写「10 万+」「刷屏」「全网爆款」**，不编造数字；
- 检索结果只能证明「被搜到/被转载」，不等于「读者喜欢」，在交付里讲清这个差别。

### 路线 C：用户指定篇目（最省事，也最贴合他的口味）

用户给了链接或文章名，直接读取全文；先问一句「你希望借鉴它的哪一点——标题、结构、
语气还是选题角度」，避免整篇照搬。

三路都拿不到（无检索能力、账号无历史数据、用户也没给）时：明说「本轮没有外部对标，
按内置爆文结构骨架写」，并在交付里标注这是无对标成稿，选题风险由用户承担。

## 第三步：拆解（每篇填一张表）

```
篇名 / 来源 / 发布时间 / 热度证据（真实数据或"未验证"）

1. 标题：字数、句式类型（数字结果 / 反常识 / 身份代入 / 疑问 / 场景）、承诺了什么
2. 首屏前 100 字：开场方式（场景 / 对话 / 冲突 / 结论 / 提问）、是否点到读者、有无数字
3. 结构骨架：按顺序列出小标题，标注每段的功能（共鸣 / 反转 / 论证 / 案例 / 升华 / 转化）
4. 节奏：段落行数、句长、小标题间隔字数、加粗与金句密度、配图位置
5. 素材类型：故事 / 数据 / 对话 / 对照实验 / 清单 / 引述
6. 情绪曲线：焦虑→好奇→顿悟→行动→转发，标出曲线顶点在哪一段
7. 转发理由：读者为什么会转（替我说话 / 显得我懂 / 帮到别人 / 站队）
8. 结尾：互动提问 / 关键词 / 关注引导 / 无
9. 口吻：自称与对读者的称呼、距离感、情绪浓度、口头禅（本号文章直接写进口吻卡；他号只作参考，不模仿他人身份）
10. 可迁移技法（只写技法）：___
11. 不可迁移（它独有的事实、身份、时机）：___
```

## 第四步：提炼「可迁移技法」，落到自己的提纲

把 3–5 篇的第 10 项归并，通常能收敛出 2–4 条技法，例如：

- 「先讲一个具体到工位级别的小场景，再讲道理」；
- 「每小标题都是一句带观点的短句，不是名词短语」；
- 「数据用对照式：之前 X，之后 Y」；
- 「结尾给一个可立刻执行的一步，不是总结全文」。

**红线**：

- 洗稿：不沿用原文的案例、故事、数据、论证顺序和独特表达；换骨架不换血肉。
- 搬运：不复制原文段落、金句或图片；引用必须转述并标明出处。
- 夸大：不把别人的结论搬到自己的主题下；不可迁移的部分（第 11 项）一律不用。
- 合规：不用未核实的名人言论、医疗/金融效果承诺、绝对化用词。

## 第五步：写成提纲再动笔

技法确定后先把提纲给用户过一遍（提纲改起来比成稿便宜十倍）。提纲按段写清：

```
段N | 小标题（一句观点） | 这段的任务（共鸣/反转/论证/案例/升华/转化） | 用哪个素材 | 目标字数 | 是否配图
```

提纲确认后按 [editorial.md](editorial.md) 写初稿、按 [voice.md](voice.md) 去 AI 味，
再跑 `scripts/build_article.py` 体检并渲染。

## 交付时说清对标结论

给用户的一段话里必须包含：对标池几篇、来源类型、热度证据是否验证、
借用了哪些技法、本篇与对标文章的差异在哪。含糊地说「参考了爆款写法」等于没说。
