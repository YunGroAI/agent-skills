# 选题与写作

**顺序不可颠倒**：主题简报 → 热门对标 → 提纲 → 成稿 → 体检 → 定稿。
跳过对标直接写，是文章「生硬、像通稿、没人读完」的主要原因。

- 主题简报与热门对标：[benchmarking.md](benchmarking.md)
- 版式与主题：[themes.md](themes.md)；配图：[imagery.md](imagery.md)
- 排版与发表：[publishing.md](publishing.md)

## 1. 主题简报

先合并 Playbook、用户本轮要求和可用历史信息。至少锁定：主题切口、读者处境、主目标
（`reach` / `follower_growth` / `leads` / `trust`）、可用素材、禁区。
用一段话回显简报让用户确认，只补问真正会影响结果的信息。

**素材决定成败**：手上没有真实案例、数据或经历时，第一轮就问出来。
没有素材又不补，就只能写成正确的废话——这时要明说「这篇会偏泛」，不要硬写成干货。

## 2. 先对标，再动笔

按 [benchmarking.md](benchmarking.md) 建立 3–5 篇对标池（账号自有爆款优先，其次联网检索，
再次用户指定），拆出 2–4 条可迁移技法，写进提纲。

只有以下情况可以不跑对标：用户明确说「直接写/不用参考」、纯内部通知类短文、或复盘中已确定写法。
跳过对标就在交付里写明「本轮无外部对标」。

## 3. 选题卡

引导模式给恰好 3 张卡，每张包含：一句话选题、读者痛点、核心角度、**借用的对标技法**、
需要的素材、传播钩子、风险和推荐理由。

潜力分（权重为可调经验值）：受众匹配 25、读者价值 20、时效/差异化 20、证据可信度 20、
分享潜力 15。分数只用于比较方向，不是阅读量预测。快捷模式选总分最高且风险可控的方向，
并说明为什么选它。

## 4. 标题

给 3 个候选并标推荐项，三类各一：

| 类型 | 写法 | 示例骨架 |
|---|---|---|
| 直接价值 | 具体结果 + 可兑现的方法 | 「3 个动作，把周报从三屏压到一屏」 |
| 反差/冲突 | 常识对立面 + 身份代入 | 「我用 AI 写周报，被领导叫去谈话了」 |
| 场景/故事 | 具体时间地点 + 悬念 | 「周五下午四点，我删掉了写好的三页」 |

- 20–28 字、手机两行内；含数字、第二人称或冲突；不用形容词堆砌和名词短语。
- 标题承诺必须在正文兑现。不用伪造数字、虚假稀缺、夸大保证、与内容无关的情绪刺激。

## 5. 结构骨架

三种骨架选一种，不混用：

- **知识/方法文**：痛点场景 → 为什么老办法不行 → 新框架 → 分步演示 → 今天就做的一步
- **故事/观点文**：钩子冲突 → 具体经过 → 转折（认知被推翻）→ 洞察 → 给读者的结论
- **转化文**：读者处境 → 证据（数据/案例）→ 解法 → 信任（真实细节）→ CTA

通用节奏（爆文最常见的一条线）：
**具体场景开场 → 说到读者的痛点 → 认知反转 → 分点给出方法/论证 → 一个高潮金句 → 结论卡 → 互动或 CTA。**

小标题规则：

- 每个小标题是一句**带观点的短句**（≤20 字），不是「方法论」「案例分析」这种名词短语。
- 每 300–500 字一个小标题；全文至少 3 个。
- 小标题连起来读，应该能看出全文的论证链。

## 6. 手机节奏参数

| 项 | 目标值 |
|---|---|
| 首屏 | 前 100–150 字内给出场景、冲突、结论或数字，直接回答「这与我有什么关系」 |
| 段落 | 3–4 行一段（约 60–120 字），超过就拆 |
| 句子 | 平均 20–30 字，长短句交错；长句最多留一句做强调 |
| 小标题间隔 | ≤ 500 字 |
| 配图 | 每 400–600 字一张，长文 3–5 张 |
| 金句 | 每 800 字至少一句可截图的独立短句 |
| 结尾 | 一个读者能回答的问题，或一个立刻可做的一步 |

## 7. 语言纪律

**禁止开场**：随着…、在当今…、近年来、众所周知、综上所述、什么是 X、本文将介绍…。
第一句就进场景、冲突、数字或结论。

**替换掉这些词**（出现即改）：赋能、抓手、闭环、沉淀、颗粒度、对齐、生态位、深度融合、
全方位、多维度、进一步、持续深耕、稳步推进、显著改善、具有重要意义、保驾护航、
综上所述、值得注意的是、由此可见、开启新篇章。

**具体化规则**：

- 写「一个人、一次事、一个数字」，不写「很多人普遍存在」。
- 用第二人称「你」；用口语连接词（其实、结果、后来、说白了、换个做法）。
- 抽象判断后面必须跟例子或数字，否则删掉这个判断。
- 能删的字都删：写完再砍掉 20%，砍不动的说明还有废话。
- 引用优先转述并标明来源；资料不足就保留不确定性，不把假设写成事实。

## 8. 情绪曲线与转发理由

安排一条曲线，让读者有地方被戳中：**共鸣（这说的就是我）→ 好奇/焦虑（那怎么办）→
顿悟（原来是这样）→ 可执行（我今天就能试）→ 转发理由。**

**转发理由要写进文章里**，缺了它就没有传播：替读者说出他想说的话、让他显得懂行、
让他能帮到别人、或给出一个明确的立场。结尾不要写「感谢阅读」「以上就是全部内容」。

## 9. 改写 SOP（参考热门文章逻辑时）

1. 锁定主题简报 → 建立对标池 → 拆出可迁移技法（不搬事实与案例）。
2. 出提纲：每段写清「任务 / 素材 / 情绪 / 目标字数 / 是否配图」，先给用户过一遍。
3. 按提纲成稿，先写完再改，边写边润色会拖慢节奏。
4. 一条命令完成体检 + 渲染（体检只报告不改稿，按报告逐项改；有 ERROR 时不渲染）：

   ```bash
   python3 scripts/build_article.py 正文.md -o out.html
   ```

5. **朗读一遍**：拗口的地方就地改短，读不顺的段落通常是结构问题不是措辞问题。
6. 定稿后再进 [themes.md](themes.md) 选主题、按 [imagery.md](imagery.md) 出配图。

## 10. 定稿门槛

排版前逐项通过：

- 事实、日期、人物、数字和链接可回溯；事实与观点明确区分。
- 标题和导语给的期待，正文都兑现了。
- `lint_article.py` 的 ERROR 清零，WARN 有明确理由保留。
- 首屏 100 字内能说清「这与读者有什么关系」，全文无开场套话。
- 每个抽象判断后面都有具体例子或数字；没有「正确的废话」段落。
- 读者有清晰的新信息、判断框架或可执行步骤；同义重复和空泛口号已删除。
- 有明确的转发理由和结尾互动/行动项。
- 语气、用词、CTA 和禁区符合 Playbook；案例与用户故事不泄露私密信息。
- 反方审读：写出最可能被质疑的点，补证据、降低断言强度或明确范围。
