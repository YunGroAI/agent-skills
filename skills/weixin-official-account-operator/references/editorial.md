# 选题与写作

**顺序不可颠倒**：主题简报 → 口吻卡与素材采访 → 热门对标 → 选题 + 模板 + 提纲 → 初稿 →
去 AI 味改稿 → 体检与标题评分 → 定稿。

文章生硬、像 AI，几乎都是前三步缺位造成的：不知道谁在说话、手上没有真实细节、
没看过同赛道的好文章。这时在措辞上反复润色是白费力气，先回到前面补齐。

- 口吻、素材采访、情绪表达与去 AI 味：[voice.md](voice.md)
- 场景写作模板：[templates.md](templates.md)
- 主题简报与热门对标：[benchmarking.md](benchmarking.md)
- 版式与主题：[themes.md](themes.md)；配图：[imagery.md](imagery.md)
- 排版与发表：[publishing.md](publishing.md)

## 1. 主题简报

先合并用户给出的运营偏好、本轮要求和可用历史信息。至少锁定：主题切口、读者处境、主目标
（`reach` / `follower_growth` / `leads` / `trust`）、可用素材、禁区。
用一段话回显简报让用户确认，只补问真正会影响结果的信息。

## 2. 口吻卡与素材采访（每篇必走）

按 [voice.md](voice.md) 第 1、2 节：

- **口吻卡**：从账号历史文章或用户样文提取「谁在说话」；没有就问三个问题。
- **素材采访**：按主题一次问 3–5 个问题，拿到场景、原话、感受、代价、数字。

两件事与主题简报合并成一轮提问，不拆成多轮。用户只想快点出稿时，至少问一句
「有没有一个真实的场景或例子可以放进去？」——一个真实细节，胜过十条写作规则。

用户确实没有素材时明说「这篇会偏泛、情绪偏弱」，改写成观点/方法文，不虚构亲身经历。

## 3. 先对标，再动笔

按 [benchmarking.md](benchmarking.md) 建立 3–5 篇对标池（账号自有爆款优先，其次联网检索，
再次用户指定），拆出 2–4 条可迁移技法，写进提纲。

只有以下情况可以不跑对标：用户明确说「直接写/不用参考」、纯内部通知类短文、或复盘中已确定写法。
跳过对标就在交付里写明「本轮无外部对标」。

## 4. 选题卡与标题

### 选题卡

引导模式给恰好 3 张卡，每张包含：一句话选题、读者痛点、核心角度、**选用的场景模板**
（见 [templates.md](templates.md)）、借用的对标技法、需要的素材、传播钩子、风险和推荐理由。

潜力分（权重为可调经验值）：受众匹配 25、读者价值 20、时效/差异化 20、证据可信度 20、
分享潜力 15。分数只用于比较方向，不是阅读量预测。快捷模式选总分最高且风险可控的方向，
并说明为什么选它。

### 标题

给 3–5 个候选并标推荐项，至少覆盖三类：

| 类型 | 写法 | 示例骨架 |
|---|---|---|
| 直接价值 | 具体结果 + 可兑现的方法 | 「3 个动作，把周报从三屏压到一屏」 |
| 反差/冲突 | 常识对立面 + 身份代入 | 「我用 AI 写周报，被领导叫去谈话了」 |
| 场景/故事 | 具体时间地点 + 悬念 | 「周五下午四点，我删掉了写好的三页」 |

- 手机两行内（约 12–28 字）；有具体对象、数字、第二人称或冲突中的至少一项。
- 像人说的话，不像广告：少用「竟然、震惊、必看、干货」这类词。
- 标题承诺必须在正文兑现。不用伪造数字、虚假稀缺、夸大保证、与内容无关的情绪刺激。
- 候选写好后跑评分，把分数和扣分原因一起给用户参考：

  ```bash
  python3 scripts/score_title.py "标题一" "标题二" "标题三"
  ```

  评分是启发式规则，只用于比较候选、发现明显毛病，不代表打开率；最终由用户选。

## 5. 模板与提纲

按选定的场景模板写提纲，每段写清：

```
段N | 小标题（一句观点） | 任务（共鸣/反转/论证/案例/升华/转化） | 用哪个真实素材 | 情绪 | 目标字数 | 是否配图
```

- 「用哪个真实素材」一栏不能空；空着的段落写出来一定是空话，要么补素材要么删段。
- 标出全文唯一的**情绪主峰**在哪一段。
- 小标题是一句**带观点的短句**（≤20 字），连起来读能看出全文的论证链；
  不用「方法论」「案例分析」这类名词短语。

## 6. 初稿：先写完，再改

- 按口吻卡写，想象在给一个具体的读者讲这件事，而不是在「输出内容」。
- 第一句直接进场景、冲突、原话或结论，不铺垫。
- 先一口气写完，不边写边润色；改稿交给第 7 步。

## 7. 去 AI 味改稿

按 [voice.md](voice.md) 第 4、5 节的清单和五遍改稿 SOP 处理初稿：结构 → 口吻 → 细节 → 节奏 → 朗读。
然后一条命令完成体检 + 渲染（体检只报告不改稿；有 ERROR 时不渲染）：

```bash
python3 scripts/build_article.py 正文.md -o out.html
```

## 8. 手机阅读参考值

以下是常见的手机阅读舒适区，**用来发现问题，不是要逐项凑数**。
为了凑指标而硬塞数字、金句、小标题，正是 AI 味的来源之一。

| 项 | 参考值 |
|---|---|
| 首屏 | 前 100–150 字内让读者知道「这跟我有什么关系」 |
| 段落 | 一般 3–4 行（约 60–120 字），允许一句话成段制造停顿 |
| 句子 | 长短交错；连续三句长句就该断一断 |
| 小标题间隔 | 通常 300–500 字一个；故事类可以更长，用分隔线代替 |
| 配图 | 每 400–600 字一张，长文 3–5 张；没有好图宁可不配 |
| 金句 | 自然出现就加粗或做成结论卡，不刻意制造 |
| 结尾 | 回到开头的场景、一个读者能回答的问题，或一个立刻可做的一步 |

## 9. 语言纪律

**禁止开场**：随着…、在当今…、近年来、众所周知、在这个…的时代、你是否也曾…、
什么是 X、本文将介绍…。

**替换掉这些词**（出现即改）：赋能、抓手、闭环、沉淀、颗粒度、对齐、生态位、深度融合、
全方位、多维度、进一步、持续深耕、稳步推进、显著改善、具有重要意义、保驾护航、
综上所述、值得注意的是、由此可见、开启新篇章、总而言之、让我们一起。

**具体化规则**：

- 写「一个人、一次事、一个数字、一句原话」，不写「很多人普遍存在」。
- 用口吻卡规定的自称和对读者的称呼；口语连接词（其实、结果、后来、说白了）多于书面连接词。
- 抽象判断后面跟例子或数字，否则删掉这个判断。
- 能删的字都删：写完再砍掉 20%，砍不动的说明还有废话。
- 引用优先转述并标明来源；资料不足就保留不确定性，不把假设写成事实。
- 广告法极限词（最、第一、顶级、国家级、100% 等）和效果承诺不用，转化文尤其注意。

## 10. 情绪曲线与转发理由

情绪表达的具体技法见 [voice.md](voice.md) 第 3 节。整篇安排一条曲线：
**共鸣（这说的就是我）→ 好奇/焦虑（那怎么办）→ 顿悟（原来是这样）→ 可执行（我今天就能试）。**
一篇一个主峰，先事后情，克制胜过煽情。

**转发理由要写进文章里**：替读者说出他想说的话、让他显得懂行、让他能帮到别人、
或给出一个明确的立场。结尾不要写「感谢阅读」「以上就是全部内容」「希望对你有帮助」。

## 11. 定稿门槛

排版前逐项通过：

- **像人写的**：朗读一遍不像念稿；口吻与口吻卡一致；全文至少有一个只属于这篇的真实细节或原话。
- 事实、日期、人物、数字和链接可回溯；事实与观点明确区分；没有虚构的亲历和对话。
- 标题和导语给的期待，正文都兑现了。
- `lint_article.py` 的 ERROR 清零，WARN 有明确理由保留。
- 首屏 100 字内能说清「这与读者有什么关系」，全文无开场套话和总结式结尾。
- 读者有清晰的新信息、判断框架或可执行步骤；同义重复和空泛口号已删除。
- 有明确的转发理由和结尾互动/行动项。
- 语气、用词、CTA 和禁区符合用户给出的偏好；案例与用户故事不泄露私密信息。
- 反方审读：写出最可能被质疑的点，补证据、降低断言强度或明确范围。

交付时附一句「本篇用了哪些真实素材、口吻按什么定的」，让用户一眼判断像不像自己。
