# 封面与配图：让人一眼看出主题

配图不是写完文章再补的装饰，而是和提纲一起定的「视觉脚本」。
封面和每张正文图都要满足两件事：**一眼能看出这篇在讲什么**，**观感上属于同一套设计方案**。
抽象光效、无字几何图、与主题无关的氛围图，缩成转发卡片后读者认不出主题，一律不当封面用。

封面、配图都由 Agent 按选题自动完成，**不单独停下来让用户确认**；成品放进成稿确认卡一起批准
（[interaction-cards.md](interaction-cards.md) 第 3 节）。

## 何时进入本文件

- 写新文章：定稿、排版方案定下之后，渲染入草稿之前（每篇必走，不允许「无配图」交付）。
- 用户提到配图、封面、插图、「图要好看」「看不出主题」「图和文不搭」。
- 已入草稿的文章要换封面或配图（按 [publishing.md](publishing.md)「已入草稿后的修改」直接更新，不重新确认）。

## 第一步：定主题视觉锚点（一切图的源头）

先用四行写出这篇的「视觉锚点」，封面、刊头、信息图和结论卡都从这四行取材，整篇反复出现同一个意象：

| 项 | 写什么 | 例（美国禁用 DeepSeek 一文） |
|---|---|---|
| 主题词 | 读者一眼要认出的对象，≤ 8 字 | 美国禁用 / DeepSeek |
| 冲突或动作 | 这件事最反直觉、最有张力的一句，≤ 16 字 | 连“底下跑着它”的产品，也要拆 |
| 视觉隐喻 | 1–2 个能画出来的意象，从 `make_visuals.py --list` 的图标里挑 | 政府建筑 + 模型网络，放大镜一路查到底 |
| 栏目标签 | 栏目 · 领域，和刊头一致 | 观点 · 中美 AI |

检验：只看主题词和冲突句，一个没读过文章的人能不能说出「这篇讲的是什么、为什么值得点开」。说不出就重写，
不要靠配色和图标补救。主题词沿用标题里的核心名词，冲突句沿用标题或导语的承诺，不另造口号；
事实性的说法要和正文一致（如禁令的范围），不为醒目而夸大。

## 第二步：写配图脚本

按提纲逐段标注，先出这张表再生成任何一张图：

| 位置 | 角色 | 要传达的一件事 | 图形 | 与锚点的关系 |
|---|---|---|---|---|
| 封面 | 2.35:1 + 1:1 | 主题词 + 冲突句 | 大字报（默认） | 直接用锚点文字，两侧放视觉隐喻 |
| 第一个论证段后 | 范围/对照 | 读者最容易误解的边界 | `compare` | 高亮读者最该注意的那一条 |
| 中段转折处 | 链路/转变 | 文章的核心判断 | `stack` / `shift` | 重复封面的视觉隐喻（如放大镜） |
| 有时间脉络或关键数字时 | 证据 | 一组时间节点或一个数字 | `timeline` / `bignum` | 最后一个节点或数字用强调色 |

- 篇幅：每 400–600 字一张，长文 3–4 张，短文 1–2 张；**每张图对应一个论证节点**，不重复正文已有的组件
  （正文已经用了 `:::steps` 时间线，就不再画 `timeline`）。
- 图里的每个事实都必须在正文里出现过；图只做「结构化重述」，不引入新数字、新说法。
- 图放在它说明的那一节末尾；图注写图里没有的信息（出处、口径、一句点评），不复述正文。

## 第三步：生成

### 默认：本地脚本出图（任何环境都能用）

`scripts/make_visuals.py` 按一份 JSON 规格生成大字报封面和正文信息图，颜色取设计方案的主色/强调色，
字体自动查找系统中文字体（找不到时 `--font` 指定）。需要 Pillow。

```bash
python3 scripts/make_visuals.py --list                      # 图形类型与图标
python3 scripts/make_visuals.py --example > 配图.json        # 完整示例规格（即上面那篇的封面与 3 张图）
python3 scripts/make_visuals.py 配图.json -o wx_images --design 方案.json
```

规格结构（字段含义见 `--example`）：

```json
{
  "anchor": "一句话视觉锚点，只作记录",
  "cover": {"kicker": "观点 · 中美 AI", "headline": "美国禁用", "highlight": "DeepSeek",
            "subline": "连“底下跑着它”的产品，也要拆", "motifs": ["building", "network"]},
  "figures": [
    {"name": "fig1_scope", "type": "compare", "left": {"title": "…", "items": ["…"], "emphasis": 2},
     "right": {"title": "…", "items": [["标题", "说明"]]}},
    {"name": "fig2_stack", "type": "stack", "layers": [["表层", "说明"], ["底层", "说明"]], "label": "…"},
    {"name": "fig3_shift", "type": "shift", "before": {"motif": "chip", "title": "…"},
     "after": {"motif": "network", "title": "…", "focus": true}, "tags": ["…"]}
  ]
}
```

大字报封面的写法：

- `headline` 写主题词（≤ 6 个汉字最醒目，可用 `\n` 分两行）；`highlight` 放最该被认出的专名或数字，
  用强调色满底块；`subline` 写冲突句；`kicker` 写栏目标签。文字全部排在画面正中的 1:1 安全区里，
  转发卡片也完整。
- `motifs` 选 0–2 个视觉隐喻放在两侧（只在 2.35:1 版可见），没有贴切的就不放，不硬凑。
- 节日、生活类选题同样用大字报：主题词写节日或场景（「重阳节」），冲突句写具体利益点（「三条不累人的近郊路线」）。

脚本输出 `cover_235.jpg`、`cover_11.jpg` 和每张图的 JPEG，已满足上传要求；**不要再用 `prepare_image.py` 默认参数处理**
（它会裁掉上下边缘去水印，会切掉图里的文字），只用 `--check-only` 复核。

### 当前 Agent 有图片生成工具时

可以额外生成场景图（人物、动作、具体环境）放在首屏后或收尾前，按下面的 prompt 写法；但**封面仍用大字报**，
除非用户给了真实照片或明确要求照片封面——即便如此也要在照片上叠加主题词（用 `make_visuals.py` 的规格另出一版对比）。

生成模型的 prompt 一次只描述一张图：

```
[主体 + 动作/状态] ，[环境/场景] ，[镜头与构图：特写/中景/横构图 2.35:1] ，
[光线：自然侧光/柔光/冷光] ，[色调：<方案配色的 image_tone>] ，[质感：<调性对应质感>] ，
no text, no letters, no logos, no watermarks
```

- 生成模型写中文几乎必然乱码，所以**生成图上不要文字**；需要文字的图（封面、信息图）一律用 `make_visuals.py` 出。
- 不指定真实品牌、logo、真实人物肖像；不把生成图当作新闻纪实照片使用。
- 生成后用 `prepare_image.py` 处理（这时默认裁边是合适的）。

### 色调与质感

所有图共用设计方案的主色与强调色（`--design 方案.json`）。生成图的色调取配色的 `image_tone`，质感按调性：

| 调性 | 质感与构图 |
|---|---|
| 稳重商务 `business` | 冷静、对称、办公真实场景 |
| 理性科技 `tech` | 几何、光感、抽象但克制 |
| 温暖叙事 `warm` | 自然光、人物近景、生活质感 |
| 清爽干货 `fresh` | 干净、明亮、留白多 |
| 深度评论 `editorial` | 强对比、纪实、粗颗粒 |
| 严谨教程 `tutorial` | 简洁图示感、数据感 |
| 活力促销 `promo` | 动感、满构图、强对比 |
| 东方雅致 `oriental` | 留白、水墨、器物静物 |
| 节庆喜庆 `festive` | 节日元素、暖光、团聚 |
| 生活美学 `lifestyle` | 胶片感、浅景深、生活静物 |

## 第四步：自检后直接进入下一步（不停顿）

生成后 Agent 自己逐张看图（读取图片文件），发现问题就改规格重出，**不把半成品拿给用户挑**：

- [ ] 把 `cover_11.jpg` 想象成转发卡片里的小方图：主题词仍能一眼读出，没有被裁掉或压住。
- [ ] 封面主题词和标题一致，冲突句不夸大正文事实。
- [ ] 每张信息图对应配图脚本里的一行，文字不溢出、不重叠、不贴边；高亮只给一处。
- [ ] 全套图同一主色与强调色，同一套图标语言；封面的视觉隐喻在至少一张正文图里再次出现。
- [ ] 生成图（如有）无文字、无水印、无 logo、无真实品牌与人物。
- [ ] 图注不是正文的复述；`![说明](文件)` 的说明同时是 alt。

通过后把图插进正文对应位置（`![图注](wx_images/fig1_scope.jpg)`），重新渲染，进入成稿确认卡；
用户批准入草稿后再上传（封面拿 `media_id`，正文图换成 mmbiz URL，见 [publishing.md](publishing.md)「图片上传」）。
图片链路不通时的兜底与错误码判定见 [publishing.md](publishing.md)；走手动通道就要如实说明图没有进草稿。
