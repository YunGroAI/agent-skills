# 交互卡片：公众号运营各节点怎么问

本文件把 SKILL.md「交互规范」落到公众号流程的每个停顿点。原则不变：**先替用户想好，再让用户点选或微调**。
下面的卡片是格式示例，选项内容必须按本次用户意图、账号历史和已读到的数据现场生成，不照抄示例文字。

通用写法：

- 一张卡 = 一个问题 + 2–4 个选项 + 「其他 / 我来补充」。推荐项放第一个并标「（推荐）」，附一句理由。
- 一组卡最多 4 个问题；问题之间有依赖时（例如先选账号才能读历史文章）分两组问。
- 能从上下文推断的项直接写进回显卡，不再单独出卡。
- Agent 没有选项卡片工具时，用编号列表呈现，提示「回编号即可，可多选或补一句话」。

## 1. 账号绑定卡（每个会话一次）

```text
这次会话操作哪个公众号？
1. 「某某科技」…abc123（推荐：默认第一个账号）
2. 「某某生活」…def456
3. 新增公众号（扫码授权）
```

- 第一个账号默认选中；用户请求里已点名账号时直接绑定并回显一行，不出卡。
- 只有一个账号时也出这张卡（这个账号 / 新增公众号），让用户知道本次在操作哪个号。
- 没有可用公众号时：「1. 扫码新增（推荐） 2. 去平台「业务账号」页连接 3. 先只做本地写作」。
- 新增流程见 SKILL.md「扫码新增公众号」；扫码后再给一张卡：
  「1. 我已完成授权（推荐） 2. 二维码过期，重新生成 3. 取消新增」。

## 2. 开写卡（主题简报 + 口吻 + 素材，一轮问完）

先读账号近期文章，推断切口、读者和口吻，再出一组卡，替代逐项提问：

```text
① 这篇写哪个切口？
   1. 中小企业用 AI 写周报的 3 个坑 —— 给被周报折磨的部门主管（推荐：贴合账号近 3 篇高读文章）
   2. 我用 AI 写了一个月周报，老板发现了吗 —— 经历复盘，情绪更强
   3. 周报模板 + 提示词合集 —— 方法干货，易收藏
   4. 其他 / 我来补充
② 这篇最想要什么效果？
   1. 多些人读、多转发（推荐） 2. 涨粉 3. 带来咨询或线索 4. 建立专业信任
③ 用什么口吻？
   1. 按账号历史：自称「我」，同行聊天，克制偶尔自嘲（推荐） 2. 像朋友聊天 3. 像老师讲课 4. 其他
④ 手上有真实素材吗？
   1. 有亲身经历，我回几句就行（推荐：最能写出人味）
   2. 有数据或客户案例
   3. 没有，写成观点 / 方法文（会偏泛、情绪偏弱）
```

目标选项对应 `reach` / `follower_growth` / `leads` / `trust`，卡片上只写用户的话。
禁区默认按账号历史推断（不点名客户、不做绝对化承诺），写进回显卡里由用户调整。

用户选了有素材时，按 [人味写作](voice.md) 第 2 节和 [场景写作模板](templates.md) 挑 3–5 个采访问题，
**每个问题附一个示例答法**，降低回答门槛，例如：「最卡的是哪一刻？（例：周五四点被退回第三版）」。

## 3. 简报回显卡（确认后才对标）

```text
本篇简报：
- 切口：中小企业用 AI 写周报的 3 个坑
- 读者：被周报折磨的部门主管 ｜ 目标：多些人读、多转发
- 口吻：「我」+「你」，同行聊天，克制
- 素材：你提供的「第三版被退回」经历
- 禁区：不点名客户，不承诺效果
1. 没问题，开始找对标（推荐）  2. 调整某一项（说哪项改成什么）  3. 换个方向
```

## 4. 选题 + 提纲卡（对标后只停一次）

一次给 3 个可比选题，并附推荐选题的模板与逐段提纲：

```text
推荐：A《……》经历复盘模板，理由：对标里同类结构读者停留最长
  提纲：开场（场景）→ 第一个坑 → …… → 结尾（回到开头）
1. 用 A 和这份提纲开写（推荐）
2. 换成 B《……》（方法干货，更易收藏）
3. 换成 C《……》（观点评论，更有争议）
4. 调整提纲（说改哪一段）
```

## 5. 标题卡

候选跑过 `score_title.py` 后按分数排序，分数只作参考：

```text
选一个标题（分数为启发式参考，不代表打开率）：
1. 《……》82 分（推荐：有具体对象和数字）
2. 《……》76 分（更有悬念）
3. 《……》71 分（更稳妥）
4. 我自己改一个
```

## 6. 主题风格卡（定稿后、渲染前）

引导模式下每篇都出一次主题卡，让用户按自己的文章选风格；用户已点名主题、要求沿用上次风格或走快捷模式时不出卡，
直接用并在回显里说明。

**第一步：选主题。** 选项来自 `python3 scripts/render_theme.py 正文.md --cards`（推荐前 3 + 兜底项，
每项已带名称、一句调性、适合场景和推荐依据），同时生成用这篇文章渲染的对比页让用户看图选：

```bash
python3 scripts/render_theme.py 正文.md --compare 主题对比.html     # 默认对比推荐前 3 套
```

```text
这篇用哪套排版？（已生成「主题对比.html」，编号与下面一致，可以先看效果）
1. 杂志编辑 magazine（推荐）—— 编辑部气质，适合深度长文；依据：观点评论、引语多
2. 专业商务 professional —— 沉稳克制，适合行业解读、方法论
3. 温暖人文 warm —— 松弛有温度，适合人物故事、经历复盘
4. 看全部主题 / 用品牌色
```

选了第 4 项时，打开 `assets/theme-showcase.html`（全部 8 套）或用 `--compare 主题对比.html --themes a,b,c,d`
对比用户点名的几套；用户给品牌色就走 [themes.md](themes.md) 的品牌色派生。

**第二步：微调（可选，一组卡问完）。** 只在用户想调整，或账号有历史风格/品牌色时出：

```text
① 主色：1. 沿用主题配色（推荐） 2. 沿用账号近期文章主色 #xxxxxx 3. 用品牌色（告诉我色值）
② 字号与留白：1. 标准（推荐） 2. 大字宽松（中老年或长文读者） 3. 紧凑（信息密集的清单）
③ 样式组件：1. 不加，保持简洁（推荐） 2. 加金句卡 / 对比卡 3. 加文末关注引导 + 往期推荐
```

对应参数：主色 `--primary`，字号与留白 `--density large|standard|compact`，组件按 [编辑器能力](editor-kit.md)
先列出拟加的组件和位置，用户确认后再写 HTML。选定后回显一行「主题 + 主色 + 密度 + 组件」，渲染给用户看效果，
不满意随时回到第一步换主题，本地重渲染不产生任何外部副作用。

摘要卡：标题定下后给 2–3 版摘要（侧重收益 / 悬念 / 结论），推荐项写明理由，保留「我自己写」。

## 7. 执行确认卡（有副作用的动作）

按 [排版与发布](publishing.md) 的执行前确认清单展示内容，再给选项。
入草稿箱、更新草稿属于需确认动作，可以推荐「确认执行」；发表、微信预览、客服消息、删除素材或已发文章等
对外可见或不可逆动作**不标推荐**，由用户主动选中（删除素材时列出每个素材与被引用的风险，选项是「确认删除这 N 个 /
只删其中几个 / 先不删」）：

```text
即将发表到「某某科技」…abc123：标题《……》，正文为微信读回版本，发表后对外可见。
1. 确认发表
2. 先改某一项（标题 / 摘要 / 封面 / 正文）
3. 暂不发表，留在草稿箱
```

## 8. 私信处理卡

按 [私信与用户运营](engagement.md) 分类后，每类或每条一张卡：

```text
3 条意向咨询，已按 FAQ 拟好回复：
1. 按拟稿逐条发送（发送前我再复述一次对象）
2. 我改一下拟稿
3. 这批先不回
```

投诉、退款、敏感问题不给「直接发送」作推荐项。

## 9. 复盘与报错后的下一步卡

- 复盘结束给 2–3 个下一轮实验选项（例：换标题句式 / 换发文时间 / 换选题类型），推荐项附依据数据。
- 报错时按 [查询与恢复](recovery.md) 说清原因后，给出可选路径，例如：
  「1. 我去后台加 IP 白名单，加好告诉你重试（推荐） 2. 先用复制粘贴方式发 3. 先停在这里」。
