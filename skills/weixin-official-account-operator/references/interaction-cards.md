# 交互卡片：公众号运营各节点怎么问

本文件把 SKILL.md「交互规范」落到公众号流程的停顿点。原则：**先替用户想好、做好，再让用户一次点选**。
写文章到发表这条主线默认只停两次——开工卡（第 2 节）和成稿确认卡（第 3 节）；其余节点由 Agent 按推荐项自主决定，
把理由和备选攒进成稿确认卡。第 4、5 节的逐步卡片只在用户点名要自己把关、或在确认卡里要求调整时才出。
下面的卡片是格式示例，选项内容必须按本次用户意图、账号历史和已读到的数据现场生成，不照抄示例文字。

通用写法：

- 一张卡 = 一个问题 + 2–4 个选项 + 「其他 / 我来补充」。推荐项放第一个并标「（推荐）」，附一句理由。
- 一组卡最多 4 个问题；能从上下文推断的项直接写进回显行，不再单独出卡。
- **不为确认而确认**：用户原话已经给出的信息、已经批准过的内容，不再让用户重复确认；
  「我再复述一次」「确认后我再问一次」这类二次确认一律去掉，复述直接写在那张确认卡上。
- Agent 没有选项卡片工具时，用编号列表呈现，提示「回编号即可，可多选或补一句话」。

## 1. 账号绑定（并入开工卡，不单独一轮）

有多个可用公众号、且用户没点名时，作为开工卡的第一个问题：

```text
① 这次操作哪个公众号？
   1. 「某某科技」…abc123（推荐：默认第一个账号）
   2. 「某某生活」…def456
   3. 新增公众号（扫码授权）
```

- 用户点名了账号，或只有一个可用公众号时，直接绑定并回显一行「本次操作：「某某科技」…abc123，可随时切换或新增」，不出这一问。
- 账号列表和第一个账号的历史文章并行读取；用户改选其他账号时，再读那个账号的历史。
- 没有可用公众号时：「1. 扫码新增（推荐） 2. 去平台「业务账号」页连接 3. 先只做本地写作」。
- 新增流程见 SKILL.md「扫码新增公众号」；扫码后再给一张卡：
  「1. 我已完成授权（推荐） 2. 二维码过期，重新生成 3. 取消新增」。

## 2. 开工卡（动手前最多一轮）

先读账号近期文章，推断切口、读者、目标、口吻和禁区；**只把推断不出、又会改变结果的项做成问题**，
其余写成一行回显。用户原话已经给出主题和素材（或直接给了成稿）时整张卡都不出，只回显理解后开干。

```text
我的理解：给被周报折磨的部门主管写，目标多些人读和转发；口吻按账号历史（自称「我」，同行聊天，克制）；
不点名客户、不承诺效果。哪项不对直接说，不说就按这个写。

② 这篇写哪个切口？
   1. 中小企业用 AI 写周报的 3 个坑（推荐：贴合账号近 3 篇高读文章）
   2. 我用 AI 写了一个月周报，老板发现了吗 —— 经历复盘，情绪更强
   3. 周报模板 + 提示词合集 —— 方法干货，易收藏
   4. 其他 / 我来补充
③ 有没有一个真实场景？直接回一两句就够，例如：
   - 最卡的是哪一刻？（例：周五四点第三版被退回）
   - 有没有一个数字？（例：一份周报改了 5 版、花了 3 小时）
   1. 有，我直接写在回复里（推荐：最能写出人味）
   2. 没有，写成观点 / 方法文（会偏泛、情绪偏弱）
```

- 素材提示按 [人味写作](voice.md) 第 2 节和 [场景写作模板](templates.md) 挑 2–3 个最关键的问题，**每个附示例答法**，
  让用户在同一条回复里顺手答完，不另开一轮采访；用户的回答很碎也直接用，缺的细节在确认卡里标出。
- 目标对应 `reach` / `follower_growth` / `leads` / `trust`，卡片上只写用户的话。
- 交付终点（只出稿 / 入草稿箱 / 发表）不在这里问：用户说了就记下，没说就在成稿确认卡里一并选。
- 用户只答了一部分时，用已答内容和推荐值直接开干，不再追问。

## 3. 成稿确认卡（执行前一次批准）

自主完成对标、选题、写作、标题、摘要、主题、配图、渲染和只读预检之后出这一张卡。
它同时承担原来的选题卡、标题卡、主题卡和执行确认清单（清单项见 [排版与发布](publishing.md) 第 1 节）：

```text
成稿已就绪：本地预览「成稿预览.html」，手机版「手机预览.html」
- 账号：「某某科技」…abc123 ｜ 账号能力：草稿 ✓ 发表 ✓
- 标题：《周五四点，我删掉了写好的三页周报》（备选：②《……》③《……》）
- 摘要：……（备选 1 版）
- 主题：杂志编辑，主色沿用账号近期 #xxxxxx（备选：专业商务、温暖人文，对比页「主题对比.html」）
- 封面：cover_wx.jpg（2.35:1 + 1:1）；正文图 3 张
- 我替你做的决定：选了经历复盘结构（对标里同类读者停留最长）；没用「模板合集」方向；
  素材用了你说的「第三版被退回」，第 3 段缺一个具体数字，现在写成了「好几版」
- 将执行：上传封面 1 张、正文图 3 张 → 新建草稿 → 读回核对 → 发表（对外可见，不可撤回）

1. 确认执行：入草稿箱（推荐：可以先在后台再看一眼）
2. 确认执行：入草稿箱并发表（发表后对外可见，不可撤回）
3. 调整几项再看（例：标题换 ②、主题换温暖人文、第 3 段补数字，可一次说多项）
4. 先不入草稿，只要本地稿
```

- **按用户意图排序**：用户开头就说了「发表 / 直接发」时，把「入草稿箱并发表」放第一位，但不标「（推荐）」，
  此时整张卡不设推荐项；用户只说「放草稿箱」时，不列发表项，用「其他」兜底。
- 用户要微信预览且接收人已知（openid 已取得并核对）时，把第 4 项换成「确认执行：入草稿箱并发预览给「张三」」；
  接收人未知时不列，草稿建好后直接给草稿临时链接（读回即得，不需要确认）。
- 预检发现发表受限时，不列发表项，在「账号能力」写明「发表受限，草稿建好后在后台点群发即可」。
- 用户选「调整」时，本地改完重出这张卡，只标出改动的行，不重走开工卡；改动多时可附一句「其余不变」。
- 「确认执行」选项的文字必须写明动作和影响；用户选中后按 [排版与发布](publishing.md) 第 1 节一口气执行到底，
  完成后回报每一步结果（草稿 `media_id`、读回校验、发表状态或预览是否送达）。

## 4. 逐步卡片：选题、标题、摘要（仅在用户要求时）

用户说「选题我来定」「标题给我挑」时，才在对应节点停一次；否则 Agent 选推荐项，备选进成稿确认卡。

选题 + 提纲（对标后，一次给 3 个可比选题并附推荐项的模板与提纲）：

```text
推荐：A《……》经历复盘模板，理由：对标里同类结构读者停留最长
  提纲：开场（场景）→ 第一个坑 → …… → 结尾（回到开头）
1. 用 A 和这份提纲开写（推荐）
2. 换成 B《……》（方法干货，更易收藏）
3. 换成 C《……》（观点评论，更有争议）
4. 调整提纲（说改哪一段）
```

标题（候选跑过 `score_title.py` 后按分数排序，分数只作参考）：

```text
选一个标题（分数为启发式参考，不代表打开率）：
1. 《……》82 分（推荐：有具体对象和数字）
2. 《……》76 分（更有悬念）
3. 《……》71 分（更稳妥）
4. 我自己改一个
```

摘要：标题定下后给 2–3 版（侧重收益 / 悬念 / 结论），推荐项写明理由，保留「我自己写」。

## 5. 主题风格卡（用户要选风格或在确认卡里要换主题时）

默认由 Agent 按 `render_theme.py 正文.md --cards` 的第一名渲染（前两名分差 ≤ 3 时按账号历史风格取舍），
并生成 `--compare` 对比页，备选写进成稿确认卡。用户点名要自己选、或在确认卡里说「换个主题」时才出这张卡。

**第一步：选主题。** 选项来自 `--cards`（推荐前 3 + 兜底项，每项已带名称、一句调性、适合场景和推荐依据）：

```bash
python3 scripts/render_theme.py 正文.md --compare 主题对比.html     # 默认对比推荐前 3 套
```

```text
这篇用哪套排版？（已生成「主题对比.html」，编号与下面一致，可以先看效果）
1. 杂志编辑 magazine（推荐）—— 编辑部气质，适合深度长文；依据：观点评论、引语多
2. 专业商务 professional —— 沉稳克制，适合行业解读、方法论
3. 温暖人文 warm —— 松弛有温度，适合人物故事、经历复盘
4. 看全部主题 / 用品牌色
```

选了第 4 项时，打开 `assets/theme-showcase.html`（全部 8 套）或用 `--compare 主题对比.html --themes a,b,c,d`
对比用户点名的几套；用户给品牌色就走 [themes.md](themes.md) 的品牌色派生。

**第二步：微调（可选，与第一步同一轮问完）。** 只在用户想调整时出：

```text
① 主色：1. 沿用主题配色（推荐） 2. 沿用账号近期文章主色 #xxxxxx 3. 用品牌色（告诉我色值）
② 字号与留白：1. 标准（推荐） 2. 大字宽松（中老年或长文读者） 3. 紧凑（信息密集的清单）
③ 样式组件：1. 不加，保持简洁（推荐） 2. 加金句卡 / 对比卡 3. 加文末关注引导 + 往期推荐
```

对应参数：主色 `--primary`，字号与留白 `--density large|standard|compact`，组件按 [编辑器能力](editor-kit.md) 直接加，
加在哪里写进成稿确认卡，不再单独确认。本地重渲染不产生任何外部副作用，选完直接回到成稿确认卡。

## 6. 其他执行确认卡（单独的副作用动作）

不在写文章主线上的副作用动作（更新已有草稿、发表已有草稿、删除素材或已发文章、标签操作），一个任务出一张卡，
写明账号、对象、影响后给选项。可逆的动作可以推荐「确认执行」；对外可见或不可逆的动作**不标推荐**，由用户主动选中。

```text
即将发表到「某某科技」…abc123：草稿《……》（读回校验通过），发表后对外可见、不可撤回。
1. 确认执行：发表这篇草稿
2. 先改某一项（标题 / 摘要 / 封面 / 正文）
3. 暂不发表，留在草稿箱
```

删除素材时列出每个素材与被引用的风险，选项是「确认删除这 N 个 / 只删其中几个 / 先不删」。

## 7. 私信处理卡

按 [私信与用户运营](engagement.md) 分类后，每类一张卡，拟稿和接收对象直接写在卡上：

```text
3 条意向咨询，已按 FAQ 拟好回复（对象与拟稿见上）：
1. 确认发送：按拟稿回复这 3 条
2. 我改一下拟稿
3. 这批先不回
```

投诉、退款、敏感问题不给「确认发送」作推荐项。

## 8. 复盘与报错后的下一步卡

- 复盘结束给 2–3 个下一轮实验选项（例：换标题句式 / 换发文时间 / 换选题类型），推荐项附依据数据。
- 报错时按 [查询与恢复](recovery.md) 说清原因后，给出可选路径，例如：
  「1. 我去后台加 IP 白名单，加好告诉你重试（推荐） 2. 先用复制粘贴方式发 3. 先停在这里」。
